# 直接編集・直接実行の許可境界

Codex自身がユーザー明示の例外でsource・test・設定・文書を直接編集し、または運用・release・deploy・live確認を直接実行する場合に適用する。

## 許可の範囲

- 直接許可は、ユーザーが明示したaction class・成果物・変更理由へ限定される。
- 最初から具体的なsource修正・運用操作をCodexへ直接依頼したケースは、その依頼内容のまま直接実行してよい。
- 運用・release・deploy・live確認への直接許可は、その途中で新たに発生した設計変更、source・test・config・IaC・spec・docへの実装変更を自動的には許可しない。
- 同一session・同一目的・同一release・作業の連続性は、許可を別の行為へ拡張する理由にならない。

## 許可外の開発変更が必要になった場合

- 安全停止・現状保全・観測事実の整理までをCodex自身が直接行ってよい。read-onlyの診断・調査も同じく直接行ってよい。
- 未確定のarchitecture判断はSol Highが決め、実装・testは新しいGLM taskへ委譲する。
- ユーザーが「この具体的な設計変更・実装修正もCodex自身が直接行う」と改めて明示した場合だけ、例外を継続できる。
