# テスト規則
- テストが存在するコードを変更する場合、対応テストの追加・修正・実行を同じ作業単位で行う。
- テストを後回しにして実装だけを完了扱いしない。
- 実装に合わせたテストだけでなく要求から独立して何を保証すべきか確認する。
- 変更に応じて正常系・異常系・境界値・既存互換性・回帰を検証する。
- 「全部のテスト」「未テスト範囲なし」等を要求された場合、勝手に対象を狭めない。
- 網羅要求では対象関数・主要分岐とテストを照合し未テスト範囲を解消する。
- Goの網羅要求では`go test -coverprofile`と`go tool cover -func`で0%・低カバレッジ箇所を確認する。
- 未確認範囲が残る場合「すべて」「未テストなし」「完了」と報告しない。
